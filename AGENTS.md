# FoundryEngine — Agent Instructions

## Project
NeoForge Minecraft mod (`foundryengine`) that turns MC into a game engine.
- Java 25, Gradle, NeoForge MDG `net.neoforged.moddev` v2.0.140
- Package: `de.luckymcdev.foundryengine` (single project)
- Version: `0.0.65` (alpha)

## Architecture
```
src/main/java/de/luckymcdev/foundryengine/
  common/   — shared logic (cutscenes, easing, network, blueprints, bundles, world)
  client/   — client-only (ImGui editor, rendering, particles, post-processing)
  server/   — server-only (commands, dynamic packs)
  mixin/    — mixin patches
  config/   — NeoForge config (Config, ClientConfig, ServerConfig, StartupConfig)
```
- Managers via `Common.get*()` static methods
- Two event buses: `NeoForge.EVENT_BUS` + mod event bus
- Identifiers via `Common.id("path")`

## Navigation protocol (IMPORTANT — read first)
Use **IntelliJ MCP tools** for all code navigation. Do not grep/read JARs or search the filesystem for class definitions.

- **Mixin-prefixed tools are most accurate** — prefer them for symbol resolution: `mixinReferences`, `mixinImplementations`, `mixinSuperCall`, `mixinUsages`
- Other preferred tools: `references`, `implementations`, `superCall`, `usages`, `hierarchy`
- Only use text search (grep/glob) as a last resort
- MCP calls are precious — batch reads, don't re-read files you already have
- If you need info the user can provide quickly, ask instead of burning calls
- Always pass the `project` parameter where tools require it

## Entrypoints
- `FoundryEngineMod.java` — common init (mod bus + NeoForge event bus)
- `FoundryEngineModClient.java` — `@Mod(value = MODID, dist = Dist.CLIENT)`
- `FoundryEngineModServer.java` — `@Mod(value = MODID, dist = Dist.DEDICATED_SERVER)`
- `Common.java` — singleton manager access
- `client/Client.java` — client-side singleton

## Key commands
| Command                             | Purpose                              |
|-------------------------------------|--------------------------------------|
| `./gradlew.bat build`               | Full build                           |
| `./gradlew.bat preCommit`           | Check → runData → build              |
| `./gradlew.bat runClient/runServer` | Launch MC                            |
| `./gradlew.bat gameTestServer`      | Game test server                     |
| `./gradlew.bat test`                | JUnit 5 tests                        |
| `./gradlew.bat runData`             | Generate resources                   |
| `./gradlew.bat publish`             | Local Maven publish                  |
| `./gradlew.bat publishMods`         | CurseForge/Modrinth (ALPHA, dry-run) |
| `npm run docs:dev/docs:build`       | VitePress docs                       |

## Generated code
- `runData` outputs to `src/generated/resources/` (wired into sourceSets)
- `BundleDataGenerator` runs during `FMLConstructModEvent` + `commonSetup`
- Always run `runData` before committing (part of `preCommit`)

## Bundles
- `ExampleBundles/` → copied to `runs/*/FoundryEngine/bundles/` via `copyExampleBundles`
- Bundles: Groovy scripts, assets, configs, packed via `DynamicPackRepository`

## Dependencies (jarJar)
ImGui, Groovy, CommonMark, RenderDoc. JEI + Spark (runtime).

## Tests
- JUnit 5 + NeoForge testframework. Run: `./gradlew.bat test`
- Tests in `src/test/java/de/luckymcdev/foundryengine/common/`
- Game tests via `gameTestServer` run config

## Conventions
- `@NullMarked` on all packages (generated by `generatePackageInfo`)
- `@ApiStatus.Internal` for internal-only classes
- Import classes, don't use fully qualified names
- ImGui panels registered via `RegisterPanelEvent`
- No Java linter/formatter (`check` is main verification)
- VitePress in `docs/` with npm scripts
- Qodana CI code analysis
