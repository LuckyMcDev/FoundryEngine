# Bundle metadata

Every bundle carries one `.bundles.toml` file at its root. The filename must end in `.bundles.toml`; the `bundleId` field identifies the bundle. A bundle directory cannot contain multiple matching metadata files.

## Fields

```toml title="mybundle.bundles.toml"
[[bundles]]
bundleId = "mybundle"
version = "1.0.0"
displayName = "My Bundle"
authors = "Your Name"
dependencies = [
    "mod:neoforge@[26.1.2,26.2)"
]
```

| Field | Meaning |
| --- | --- |
| `bundleId` | Unique id. Used as the namespace for `Identifier`s and the script package. |
| `version` | Three numeric components in `MAJOR.MINOR.PATCH` form. |
| `displayName` | Name shown in lists and menus. |
| `authors` | Author name or a comma-separated string of names. |
| `dependencies` | Versioned mod or bundle dependencies. A range such as `mod:neoforge@[26.1.2,26.2)` accepts NeoForge 26.1.x only. |

## Optional Maven libraries

Bundles can declare Maven libraries in the same metadata object:

```toml
libraries = ["group:artifact:version", "group:other-artifact:version:sha256"]
```

The optional fourth coordinate part is the artifact's SHA-256 hash. Versions must be exact; ranges and dynamic versions are rejected.

Library loading must be enabled in the startup configuration. Use a SHA-256 value for libraries distributed to other users, and set `MAVEN_REQUIRE_SHA256` to `true` on servers that require hashes.

## The bundle id is the namespace

`bundleId` becomes the namespace of every `Identifier` you create, so `id("magic_gem")` with bundle id `mybundle` resolves to `mybundle:magic_gem`. Two bundles with the same id collide, so keep ids unique.
