# Generate data

**Applies to:** common bundle scripts for builder-generated data; custom `DataProvider` implementations are Java extensions.

FoundryEngine runs its bundle data generators during common setup. It gathers registered builders and writes generated server data and client assets to the engine's generated bundle pack. It does not use the standard Gradle `runData` task.

## What gets generated

The data generator runs over everything you registered in `BundleEvents.registry` and writes the matching JSON:

| Builder | Generated output |
| --- | --- |
| Item | Item model and language entry. |
| Block | Block state, block model, item model, language entry, and block loot table. |
| Recipe | Recipe JSON and recipe priority data. |
| Sound | Sound definitions and subtitle language entries. |
| Particle | Particle description JSON. |
| Block and item tag builders | Block and item registry tag JSON. Other registry tag types are not generated by the current providers. |

Client asset providers (models, language, sound definitions, and particle descriptions) run only on a client distribution. Server data providers run on both distributions. The registered equipment asset provider currently emits no entries.

Turn generation off per object when you want to hand-write the file instead:

```groovy
def light = BlockBuilder.create(id("invisible_light"))
        .noItem()
        .properties { it.noCollision().strength(-1.0f, 3600000.0f) }
        .generateData(false)
```

## Add your own providers

`BundleEvents.dataGen` is posted once after the per-bundle built-in generators. It exposes `addProvider(DataProvider)`, but implementing a `DataProvider` requires Java/NeoForge APIs; the bundle scripting API does not provide a built-in custom provider. Register the callback from a common entrypoint so it exists before common setup. Client and server entrypoints load too late for this event.

The generated output is available through the engine's generated data and asset pack repositories. If output is missing, inspect the startup log for generator errors and confirm that the relevant builder's data generation remains enabled.
