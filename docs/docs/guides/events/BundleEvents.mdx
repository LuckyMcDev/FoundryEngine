# BundleEvents

**Applies to:** common, client, and server bundle scripts, subject to each event's side. Custom event types are a Java extension surface.

Register callbacks by calling the method with a Groovy closure. Event callback lists clear when bundles reload; the reloaded scripts register them again.

## Registry and setup

| Registration | Timing and eligible entrypoint |
| --- | --- |
| `registry { event -> ... }` | During registry registration. Register from common entrypoints, which load during discovery. Client and server entrypoints load too late. The wrapper supports `items`, `blocks`, `recipes`, `sounds`, `particles`, `toolMaterials`, `menus`, `blockEntities`, `tags`, and generic `register`. |
| `commonSetup { event -> ... }` | NeoForge common setup. Register from common entrypoints. |
| `clientSetup { event -> ... }` | Declared in the event class, but current source has no call site for this callback; it does not fire. |
| `dedicatedServerSetup { event -> ... }` | Dedicated server setup. Register from common entrypoints; server entrypoints load when the server starts, after this setup phase. |
| `postInit { event -> ... }` | NeoForge inter-mod process event. Register from common entrypoints; server scripts load later. |

## Other callbacks

| Registration | Timing |
| --- | --- |
| `vanillaGame { event -> ... }` | A NeoForge `VanillaGameEvent` is posted. |
| `dataGen { event -> ... }` | During the engine's data-generation run. The payload is `BundleDataGenEvent`; `getLookup()` returns a `CompletableFuture<HolderLookup.Provider>`, and `addProvider` accepts a `DataProvider`. |
| `custom(EventClass, callback)` | A matching `net.neoforged.bus.api.Event` subclass is posted on the mod event bus. This requires access to the Java event class. |

## Example

```groovy
BundleEvents.registry { event ->
    event.items(gem)
    event.blocks(glow)
}

BundleEvents.commonSetup { event ->
    println "Common setup"
}
```

The engine posts the registry wrapper for each underlying registry registration event. Register before the relevant lifecycle event: registry and setup callbacks belong in common entrypoint `onLoad()`. Callback failures are reported as script errors; they do not stop later callbacks in the same event group.
