# CommandEvents

`CommandEvents.register` receives the server's `RegisterCommandsEvent`. It can be registered from common or server bundle entrypoints. Callback registrations are cleared during bundle reload; commands already installed in the dispatcher require a server restart to be rebuilt safely.

`registerClient` receives `RegisterClientCommandsEvent` on the client event bus. Register it from a client entrypoint. In an integrated world, `/engine reload` clears and re-registers these callbacks after rediscovery. A dedicated server cannot reload the callback in remote clients.

## Server command example

```groovy
import com.mojang.brigadier.Command
import net.minecraft.commands.Commands
import net.minecraft.network.chat.Component

CommandEvents.register { event ->
    event.dispatcher.register(
        Commands.literal("hello")
            .executes { context ->
                context.source.sendSuccess(Component.literal("Hello from the bundle!"), false)
                Command.SINGLE_SUCCESS
            }
    )
}
```

This uses the dispatcher accessor and success-message signature from the current Minecraft target. Keep registration inside the callback; the dispatcher is provided by the server event.
