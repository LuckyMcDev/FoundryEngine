# Sandbox and security

Bundle scripts are Groovy running inside the game process. The default policy applies class filtering, source checks, and timeouts, but scripts can still call game APIs and change game state. Treat bundles as trusted code.

## What scripts can do

Scripts can use the game and engine APIs available to their environment. The default filter blocks selected Java file, network, process, reflection, and class-loading APIs; source checks also reject selected dangerous annotations and members. These checks are best-effort, not a complete security boundary.

## The real controls

Because scripts are trusted code running as the game, the meaningful controls are about what a *server owner* is willing to run:

- **Permission to load.** Bundles are loaded from the bundle directory by the operator. A server owner decides which bundles to install. That decision is the first line of defense.
- **Command scoping.** Engine commands that change the world are operator-gated. Bundles can only use what they are given.
- **Engine path helpers.** Engine-managed file operations validate paths. The default class filter also blocks raw Java file and network APIs. Disabling the sandbox removes those restrictions, so only do it for trusted bundles.

## Configuration toggles

Several features that could be abused are switches in the common config:

| Option | Effect |
| --- | --- |
| `SCREEN_EFFECT_COMMAND_CHAINING` | Blocks `/engine screeneffect` from chaining arbitrary server commands. |
| `CUTSCENE_COMMAND_EXECUTION` | Blocks cutscenes from executing arbitrary server commands. |

These settings limit command execution through cutscene and screen-effect features. They do not grant or revoke a general script permission.

## What this means for you

- Only install bundles you trust, the way you only install mods you trust.
- If you share bundles, they run with full game access on other machines. Do not add hidden behaviour.
- The sandbox has explicit bypass controls and is best-effort. Treat bundles as trusted code and review them before installing on a server.
